# AI Agent 管理平台 · 产品想法说明（面向有命令行经验的读者）

## 1. 一句话概述
这是一个“**AI 代理管理层**”产品：不是聊天工具，而是把多个 AI 代理当作团队来管理的界面，让人用熟悉的管理方式（看板/表格/任务/状态/审阅）去协作与调度。  
**趋势判断：vibe coding 正在从“执行”转向“管理”。**

## 2. 现状痛点（从聊天到管理）
- 单聊能用，但**多代理协作不可扩展**：没有共享可见性、状态不清晰、上下文散落。  
- 人必须靠脑子做“调度与追踪”，这个脑力成本在 3~5 个代理之后陡增。  
- 代理具备执行力（改文件、跑命令、产出文档），但**缺少团队协作管理层**。  
- 越来越多人并行运行多个 agent，**任务时长从现在的半小时向 1 小时+ 拉长**，异步沟通比重提升，管理层成为必需。

## 3. 核心理念（这里的“管理”指什么）
- **管理 ≠ 工作流**：支持非线性、探索性、跨学科的协作，而不是固化流水线。  
- **管理模式复用**：把人类团队管理中成熟的模式迁移到 AI 团队。  
- **管理的三件事**：  
  1) **Attention**：用户知道该把注意力放在哪里  
  2) **Visibility**：用户知道每个 agent 在做什么  
  3) **Role**：通过角色体系不断培养与提升协作质量

## 4. 定位与目标人群
- **定位**：做一个介于 **Claude Code** 与 **Lovable** 之间的产品——不是无代码，但以管理与协作为核心。  
- **目标人群**：  
  - 多窗口、喜欢管理的 **solo engineer**  
  - 代码能力较弱但 soft skills 强的 **PM / 大厂员工 / 协作型知识工作者**

## 5. 产品核心体验（结合当前 UI）
> 下述功能既是“现有 UI 功能”也是“产品愿景的落地形态”。

### 5.1 多视图代理管理
- **表格视图（Table）**：任务级信息、状态自动更新、最适合审视与筛选。  
- **看板视图（Kanban）**：按状态列组织任务（Todo/In Progress/Review/Done/Blocked/Cancelled）。  
- **自定义视图（Customize/Whiteboard）**：为不同团队提供“像 Notion 一样可塑”的管理画布。

### 5.2 项目总览（Dashboard）
- 项目级摘要、重要文档、任务列表、最近更新、知识库记录。  
- 目标不仅是让管理者不用翻聊天，也让**代理知道全局发生了什么**，形成共享上下文。

### 5.3 Inbox（需要关注的地方）
- Inbox 用于提示**需要人介入的事项**：例如待 review、被阻塞、或风险升级。  
- 它是“提醒层”，让用户优先处理关键节点。

### 5.4 聊天 ≠ 中心，而是入口
- **Chat 仍保留**，用于即时沟通与快速确认，不是主视角。  
- **Task Router（任务路由助手）**：通过聊天理解新任务，并给出“应该分配给现有 agent 还是新建 agent”的建议；坚持“先询问再分配”。

### 5.5 文件系统与权限
- 文件列表可浏览，点击打开**全屏文档视图**。  
- 提供**分享/下载**动作；权限区分**可读 / 可写 / 不可访问**。  
- 让代理“在同一个文件系统里工作”，并能看清权限边界（**有些文件就是不让 agent 动**）。

### 5.6 代理视角与角色管理
- 代理可按状态显示、具备头像、能力标签与当前任务。  
- 角色/学徒管理（Apprentices）支持反馈记录与任务结构化复盘。  
- **Role 系统**：可定义角色的 skills 与 verification 规则（验收标准）。  
- 任务完成后自动生成结构化反馈，沉淀到角色能力与质量档案里。

## 6. 异步协作的结构化分工
- **Chat** = 即时沟通  
- **Views（表格/看板/仪表盘）** = 异步协作与可见性  
- 这种分工让团队在多代理并行、长时任务时仍能保持节奏。

## 7. 为什么对 CLI 用户友好
- 代理是“能执行命令”的实体，而非只能聊天。  
- UI 负责**管理层/策略层**，你仍可在 CLI 里把任务落地到文件、脚本、运行流程。  
- 可把“项目管理”从 terminal 的混乱中抽离出来（不要求用户放弃命令行）。

## 8. 与现有工具的差异
- **与聊天产品**：不是单聊助手，而是多代理协同管理工具。  
- **与项目管理工具**：不是给人用，而是为“代理 + 人”协同准备。  
- **与工作流工具**：不是固定流程，而是“管理画布”。

## 10. TL;DR
我们不是在造“又一个聊天 AI”。
我们在做一个**让 AI 变成团队的管理层**，把人的管理经验迁移到 AI 代理协作上，既适合懂 CLI 的人，也能被非技术协作者继承与理解。
